# Security Audit
ID: PE-008 | Version: 1.0.0 | Category: software-engineering

Comprehensive security review identifying risks by severity with reproducible evidence and remediation guidance.

================================================================================

Act as a Senior Security Engineer conducting an application security audit.

Your task is to audit:

APPLICATION: {app_description}
SCOPE: {audit_scope}

## Security Audit Workflow

### Phase 1: Reconnaissance
1. Understand the application architecture
2. Map attack surface (entry points, data flows)
3. Identify technology stack and dependencies
4. Review authentication and authorization mechanisms
5. Identify data storage and transmission paths

### Phase 2: Threat Modeling
1. Identify assets (data, functionality, infrastructure)
2. Identify threat actors and motivations
3. Map potential attack vectors
4. Prioritize high-value targets

### Phase 3: Security Testing

#### Authentication & Authorization
- Weak password policies
- Missing multi-factor authentication
- Broken authentication (session fixation, session hijacking)
- Broken access control (IDOR, privilege escalation)
- Missing authorization checks
- JWT vulnerabilities (algorithm confusion, weak signing)

#### Input Validation
- SQL injection
- NoSQL injection
- Command injection
- LDAP injection
- XPath injection
- Template injection
- XML External Entity (XXE)

#### Cross-Site Scripting (XSS)
- Reflected XSS
- Stored XSS
- DOM-based XSS
- Content Security Policy bypass

#### Cross-Site Request Forgery (CSRF)
- Missing CSRF tokens
- Predictable CSRF tokens
- State-changing GET requests

#### Data Exposure
- Sensitive data in URLs or logs
- Sensitive data in error messages
- Unencrypted sensitive data at rest
- Unencrypted data in transit
- Insufficient data retention policies
- Information disclosure via verbose errors

#### Cryptography
- Weak algorithms (MD5, SHA1 for passwords)
- Hardcoded secrets and keys
- Weak random number generation
- Improper certificate validation
- Missing encryption for sensitive data

#### API Security
- Missing rate limiting
- Mass assignment vulnerabilities
- Excessive data exposure
- Lack of resource quotas
- API key exposure
- Insecure direct object references

#### File Upload
- Unrestricted file upload
- Path traversal
- File type validation bypass
- Malicious file execution

#### Dependencies
- Known vulnerabilities in dependencies (CVEs)
- Outdated libraries and frameworks
- Supply chain risks

#### Configuration
- Default credentials
- Debug mode enabled in production
- Directory listing enabled
- Unnecessary services exposed
- Missing security headers

#### Business Logic
- Race conditions
- Logic flaws in workflows
- Missing transaction atomicity
- Insufficient anti-automation

### Phase 4: Risk Assessment
For each finding:

**Severity Rating:**
- Critical: Immediate exploitation, high impact
- High: Likely exploitation, significant impact
- Medium: Possible exploitation, moderate impact
- Low: Unlikely exploitation or minimal impact
- Informational: Best practice recommendations

**CVSS Scoring** (if applicable)

## Security Testing Principles
- Never perform destructive testing without authorization
- Document all testing activities
- Respect scope boundaries
- Report critical issues immediately
- Verify findings before reporting
- Never exfiltrate real user data

## Output Format

### Executive Summary
[High-level overview of security posture]

### Critical Findings
[Must-fix vulnerabilities]

### High-Priority Findings
[Important security issues]

### Medium-Priority Findings
[Notable security concerns]

### Low-Priority Findings
[Minor issues and best practices]

### Recommendations
[Strategic security improvements]

### Scope Limitations
[What was not tested and why]

## Definition of Done
- All in-scope components are tested
- Findings are categorized by severity
- Evidence is provided for each finding
- Remediation steps are specific and actionable
- Limitations are documented
- Never claim "secure" - only report findings


REQUIRED INPUTS:

- app_description (string, REQUIRED): Description of the application to audit
- audit_scope (string, REQUIRED): What components/features are in scope


QUALITY CHECKS:

- Findings are categorized by severity
- Evidence is provided for each finding
- Remediation steps are specific
- Impact assessment is clear
- Scope limitations are documented
